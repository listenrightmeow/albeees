# Hue Scenes deck, command listing

Generated by `tools/build_deck.py`. Paste `deck/HueScenes.deck.json` into SAMMI with side menu > Paste Deck.
Settings file: `hue_scenes.ini` in the SAMMI folder, section `[hue]`, keys `ip`, `key`, `light`, `light_type`, `light_name`, `group_id`, `scene_<slot>`, `scene_<slot>_name`, `scene_<slot>_light`.

## Hue 1: Discover  (`hueDiscover`)

1. Comment: Finds the Hue Bridge on the LAN through Hue's discovery service and saves its IP to the ini file in the SAMMI folder.
2. Delete Variable `resp`
3. Command Line: `curl.exe -sk -m 8 https://discovery.meethue.com` -> save as `resp`
4. Wait Until Variable Exists `resp` (timeout 10000 ms)
5. String Position `okPos` = position of `internalipaddress` in `/$resp$/`
6. If `okPos` > `0`  (block 3, else 1)
    7. Parse Array/Object `disc` from `/$resp$/`
    8. INI: Save Text hue_scenes.ini [hue] ip = `/$disc[0].internalipaddress$/`
    9. Alert: Hue bridge at /$disc[0].internalipaddress$/ (saved to the ini file)
    10. Popup (pauses button): Could not find the bridge automatically. /  / In the Hue app on a phone: Settings > My Hue System > tap the bridge > read the IP address. / Then click 'Hue Config: Set IP' and type it in. /  / Raw response: /$resp$/

## Hue 2: Pair  (`huePair`)

1. Comment: Mints an app key. The bridge only answers while its link button was pressed in the last 30 s.
2. INI: Load Text hue_scenes.ini [hue] ip -> `hueIp`
3. Popup (pauses button): Press the big round button on top of the Hue Bridge, then click OK within 30 seconds.
4. Delete Variable `resp`
5. Command Line: `curl.exe -sk -m 8 -X POST "https:///$hueIp$//api" -H "Content-Type: application/json" -d "{\"devicetype\":\"sammi#hue_scenes\",\"generateclientkey\":true}"` -> save as `resp`
6. Wait Until Variable Exists `resp` (timeout 10000 ms)
7. String Position `okPos` = position of `success` in `/$resp$/`
8. If `okPos` > `0`  (block 3, else 1)
    9. Parse Array/Object `pair` from `/$resp$/`
    10. INI: Save Text hue_scenes.ini [hue] key = `/$pair[0].success.username$/`
    11. Alert: Paired. App key saved to the ini file.
    12. Popup (pauses button): Pairing failed. /  / Bridge said: /$resp$/ /  / Usual cause: 'link button not pressed'. Press the bridge button again, you click Hue 2: Pair straight away. / Empty response: wrong IP (run Hue 1: Discover or Hue Config: Set IP).

## Hue 4: Test  (`hueTest`)

1. Comment: Sends a 'breathe' alert so the chosen bulb, room or zone pulses once.
2. INI: Load Text hue_scenes.ini [hue] ip -> `hueIp`
3. INI: Load Text hue_scenes.ini [hue] key -> `hueKey`
4. INI: Load Text hue_scenes.ini [hue] light -> `hueLightId`
5. INI: Load Text hue_scenes.ini [hue] light_type -> `hueLightType`
6. Delete Variable `resp`
7. Command Line: `curl.exe -sk -m 8 -X PUT "https:///$hueIp$//clip/v2/resource//$hueLightType$///$hueLightId$/" -H "hue-application-key: /$hueKey$/" -H "Content-Type: application/json" -d "{\"alert\":{\"action\":\"breathe\"}}"` -> save as `resp`
8. Wait Until Variable Exists `resp` (timeout 10000 ms)
9. Alert: Test sent, the light(s) should pulse once. Bridge said: /$resp$/

## Hue 5: Probe (optional)  (`hueProbe`)

1. Comment: Diagnostic only. Tries SAMMI's own HTTP Request against the bridge's HTTPS. The deck does not depend on this; it exists to settle the Phase 0 TLS question on real hardware.
2. INI: Load Text hue_scenes.ini [hue] ip -> `hueIp`
3. Delete Variable `probe`
4. HTTP Request GET https:///$hueIp$//api/0/config -> `probe`
5. Wait Until Variable Exists `probe` (timeout 6000 ms)
6. Popup: Native HTTPS probe. /  / If bridge config JSON appears below, SAMMI's HTTP Request accepts the bridge certificate on this PC. If you got a red HTTP error instead, the curl-based commands this deck already uses are the right choice. /  / /$probe$/
