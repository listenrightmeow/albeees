# Hue Scenes for SAMMI

A [SAMMI](https://sammi.solutions) deck that turns any SAMMI trigger into a Philips Hue change: recall a Hue scene, or set a fixed color or white temperature, on one bulb, a whole room or a zone. Everything runs on the streaming PC and talks to the Hue Bridge over your local network. No cloud service, no account, nothing to host.

## TL;DR

1. Click the copy icon on the block below. It is the whole deck.
2. In SAMMI, open the side menu and click **Paste Deck**. A deck called **Hue Scenes** appears.
3. Open the deck and run **Hue 1: Discover**, **Hue 2: Pair**, **Hue 3: Pick Target** and **Hue 4: Test**, in that order. To run a button, right-click it, choose **Edit Commands**, press **Run Button**.
4. Make a scene in the Hue app on the room or zone that holds your lights, then run **Hue: Link Scenes** and pick it.
5. Right-click **Example: Hue scene**, choose **Edit Triggers**, and add whatever should fire it. Click **Save**.

## How it works

```
trigger in SAMMI  ->  action button  ->  curl.exe  ->  Hue Bridge (HTTPS, LAN)  ->  bulbs (Zigbee)
(chat command,        reads settings      one PUT to      CLIP v2 API
 redeem, hotkey,      from hue_scenes.ini  the bridge
 timer, anything)
```

- SAMMI's **Command Line** command runs the `curl.exe` that ships with Windows 10 and 11. The deck does not use SAMMI's native HTTP Request, because the bridge's certificate is signed by Signify's private root, which SAMMI (a GameMaker application) rejects with no way to override. `curl -k` accepts it.
- Settings live in `hue_scenes.ini` in the SAMMI folder. SAMMI's variables are not kept across restarts, so every button reads the ini file before it acts.
- An action button recalls a Hue scene (the default), or sends a fixed color or white temperature to the chosen target. The target can be a single bulb, or a room or zone, which Hue exposes as one `grouped_light`.

## Requirements

- Windows 10 (1803 or newer) or Windows 11, with `curl.exe` present. Open a Command Prompt and run `where curl.exe`; it should print a path.
- SAMMI 2024.2.0 or newer.
- A Philips Hue Bridge on the same network as the PC. Any bridge that still receives updates supports the CLIP v2 API the deck uses.
- Physical access to the bridge once, to press its button during pairing.

## Setup, step by step

Run each button by right-clicking it, choosing **Edit Commands**, and pressing **Run Button**. Messages appear at the bottom of the SAMMI window.

1. **Hue 1: Discover.** Expect "Hue bridge at 192.168.x.x (saved to the ini file)". If it cannot find the bridge, open the Hue app, go to Settings, My Hue System, tap the bridge and read its IP address. Run **Hue Config: Set IP** and type it.
2. **Hue 2: Pair.** A popup tells you to press the round button on top of the bridge. Press it, then click OK within 30 seconds. Expect "Paired. App key saved to the ini file." If it says "link button not pressed", press the button again and run Pair at once.
3. **Hue 3: Pick Target.** A Notepad window opens listing every bulb, then every room, then every zone, each with a number. Type the number of what the action buttons should control into the small SAMMI popup. Pick a room or zone to drive all its bulbs at once. Expect "Action buttons will control 'Name'".
4. **Hue 4: Test.** The target pulses once.
5. **Make a scene in the Hue app.** Open the room or zone you picked in step 3, go to its scenes, add a new one, choose colors and brightness, and name it. `Scene 1` is a fine name. A scene only ever changes the lights of the room or zone it belongs to, so build it on the right one.
6. **Hue: Link Scenes.** First popup: type part of your scene's name to shorten the list, or leave it empty. Notepad opens with the scenes grouped under their room or zone, and your step 3 target is marked with an arrow. Type the number of your scene. Expect "Scene 1 -> scene 'Scene 1' in Living room (room)".
7. **Try the examples.** Run **Example: Hue scene**, then **Example: raw color (red)**, then **Reset**. The lights switch to your scene, turn red, then return to neutral white.
8. **Attach triggers.** Right-click an example button, choose **Edit Triggers**, click Add, and pick the event that should fire it. SAMMI lists every event the accounts linked to it provide. Fill in the event's condition (a chat command text, a redeem name, a minimum amount, a key combination).
9. Click **Save** at the top of the deck window.

Installing for someone else over a remote session? Follow the [Setup Guide](docs/Hue%20Scenes%20—%20Setup%20Guide.md) and hand them the [Maintenance Note](docs/Hue%20Scenes%20—%20Maintenance%20Note.md).

## The buttons

| Button | What it does |
| --- | --- |
| Hue 1: Discover | Asks Hue's discovery service for the bridge's LAN IP and saves it. |
| Hue 2: Pair | Creates an app key on the bridge after you press its button. Saves the key. |
| Hue 3: Pick Target | Lists bulbs, rooms and zones in Notepad. Saves the chosen target's id and type. |
| Hue 4: Test | Sends a breathe alert so the target pulses once. Shows the bridge's reply. |
| Hue 5: Probe (optional) | Tries SAMMI's native HTTPS against the bridge once, to show on your machine why the deck uses curl. Nothing depends on it. |
| Hue Config: Set IP | Manual fallback when discovery fails. Type the IP from the Hue app. |
| Hue: Show Settings | Shows everything saved in the ini file, including which room the linked scene is in. |
| Hue: Link Scenes | Lists the bridge's scenes grouped by room and zone, marks your target, saves the one you pick. |
| Hue: Auto rediscover | Runs by itself 15 seconds after SAMMI starts and refreshes the bridge IP. |
| Hue Scenes: how it works | A short help popup. |
| Example: Hue scene | Action button in scene mode. Recalls the linked scene. |
| Example: raw color (red) | Action button in fixed color mode. Sets red at full brightness. |
| Reset (optional) | Sets neutral white. Nothing triggers it unless you turn on the switched-off command at the end of an action button. |

The two example buttons ship with no trigger attached. Attach your own, or copy an example to make more.

## Customizing

Every knob is in the first commands of an action button. Right-click the button, choose **Edit Commands**, and you will see:

```
1. Comment     ACTION BUTTON. Attach any trigger...
2. Comment     SETTINGS - edit the values below...     <- the green comment explains each variable
3. Set Local Variable   colorMode  = 3
4. Set String Variable  sceneSlot  = 1
5. Set String Variable  brightness = 100
6. Set String Variable  colorX     = 0.6915
7. Set String Variable  colorY     = 0.3083
8. Set String Variable  whiteMirek = 370
9. Set String Variable  fadeMs     = 300
10. Comment    END OF SETTINGS...
```

To change a value, double-click the command, edit the right-hand box, click OK, then click **Save** on the deck. Leave everything below END OF SETTINGS alone. Test with **Run Button**.

### Change what fires a button

Right-click the button and choose **Edit Triggers**. Add, edit or remove triggers there. One button can have several triggers, and the same event can fire several buttons. The deck never needs rebuilding for this.

### Change how a scene looks

For a button in scene mode (`colorMode` = 3), do not touch SAMMI. Open the Hue app, open the room or zone, open the scene, and change its colors, brightness, effect or which bulbs it includes. The next trigger uses the new look.

If you delete the scene and make a new one, run **Hue: Link Scenes** again, because the new scene has a new id.

### Set a fixed color

1. Open **Edit Commands** on the button.
2. Set `colorMode` to `1`.
3. Set `colorX` and `colorY` from the table below, or convert your own color (next sections).
4. Set `brightness` from 1 to 100.
5. Optionally set `fadeMs`, the time the bulbs take to change, in milliseconds. 300 is a quick fade, 0 is instant, 2000 is slow.
6. Save, then **Run Button** to check.

| Color | `colorX` | `colorY` |
| --- | --- | --- |
| Red | 0.6915 | 0.3083 |
| Orange | 0.6 | 0.38 |
| Yellow | 0.47 | 0.47 |
| Green | 0.17 | 0.7 |
| Cyan | 0.2 | 0.33 |
| Blue | 0.1532 | 0.0475 |
| Purple | 0.2725 | 0.1096 |
| Pink | 0.45 | 0.25 |
| Neutral white | 0.3127 | 0.3290 |

The values are CIE xy coordinates, which is the only color format the Hue API accepts for color bulbs. Bulbs clamp anything outside their range to the nearest color they can make.

### Set a white temperature

1. Set `colorMode` to `2`.
2. Set `whiteMirek`. Mirek is a million divided by the color temperature in kelvin, so smaller is cooler.
3. Set `brightness` and optionally `fadeMs`. Save and test.

| Look | `whiteMirek` |
| --- | --- |
| Cool daylight (6500 K) | 153 |
| Neutral (4000 K) | 250 |
| Soft white (3000 K) | 333 |
| Warm white (2700 K) | 370 |
| Candlelight (2200 K) | 454 |
| Very warm (2000 K) | 500 |

### Pick a color from RGB or hex

The Hue API does not take RGB or hex. Convert once and type the result into `colorX` and `colorY`. Any "sRGB to CIE xy" converter on the web does this. If you prefer to do it yourself, with R, G and B scaled to 0 to 1:

1. Linearize each channel: if the value is above 0.04045 use `((v + 0.055) / 1.055) ^ 2.4`, otherwise `v / 12.92`.
2. `X = 0.664511 r + 0.154324 g + 0.162028 b`, `Y = 0.283881 r + 0.668433 g + 0.047685 b`, `Z = 0.000088 r + 0.072310 g + 0.986039 b`.
3. `colorX = X / (X + Y + Z)` and `colorY = Y / (X + Y + Z)`.

Four decimal places are plenty. Brightness is not part of xy, so set `brightness` separately.

### Add more buttons

For another fixed color: right-click **Example: raw color (red)**, copy it, paste it into the deck, rename it, change its SETTINGS and give it a trigger. Done.

For another scene, you need a second scene slot, because each slot is a line in the ini file that **Hue: Link Scenes** fills in:

1. In `tools/build_deck.py`, add to `SCENE_SLOTS`: `("2", "Scene 2")`.
2. Add an action button next to the examples, for instance `action_button("hueScene2", "Scene 2", 0.75, TEAL, scene_slot="2")`, picking a free grid position.
3. Run `python3 tools/build_deck.py` and paste the new deck into SAMMI.
4. Run **Hue: Link Scenes**. It now asks one question per slot.

### Change which lights react

Run **Hue 3: Pick Target** again and choose a different bulb, room or zone. This affects fixed color and white buttons immediately. Scene buttons follow the scene's own room or zone instead, so for those, link a scene that lives where your lights are. To cover bulbs from several rooms, make a zone in the Hue app containing them and build your scenes on the zone.

### Return to normal after a while

The last command of each action button is a switched-off **Trigger Button** that fires **Reset** after 10 seconds. To enable it, right-click that command and turn it on. Change the delay by editing its milliseconds box. Change what "normal" means by editing the SETTINGS block of the **Reset** button, or switch Reset to scene mode and link a scene for it after adding a `reset` slot as described above.

### Variable reference

| Variable | Used in mode | Meaning |
| --- | --- | --- |
| `colorMode` | all | `3` recalls the Hue scene linked for `sceneSlot`. `1` sets a fixed xy color. `2` sets a white temperature. |
| `sceneSlot` | 3 | Which linked scene to recall. The deck ships slot `1`. |
| `brightness` | 1, 2 | 1 to 100. |
| `colorX`, `colorY` | 1 | CIE xy color, 0 to 1 each. |
| `whiteMirek` | 2 | 153 (cool) to 500 (warm). |
| `fadeMs` | 1, 2 | Transition time in milliseconds. |

Values are stored as text on purpose, so what you type is exactly what reaches the bridge.

## Where settings are stored

`hue_scenes.ini` in the SAMMI folder, section `[hue]`:

| Key | Value |
| --- | --- |
| `ip` | Bridge IP address |
| `key` | Hue application key created by Pair |
| `light` | Id of the target light or grouped light |
| `light_type` | `light` or `grouped_light` |
| `light_name` | Display name of the target |
| `group_id` | Room or zone id of the target, or `none` for a single bulb |
| `scene_1`, `scene_1_name` | Linked scene id, and its name with the room or zone it belongs to |

Back this file up together with the deck. Restoring both onto a fresh SAMMI brings everything back without re-pairing.

## Limitations and design notes

- **Rate limit.** Hue allows about one command per second to a room, zone or scene. Each action button holds itself for one second after sending and has Allow Queue on, so bursts of events run in order rather than being dropped.
- **Popups do not scroll.** SAMMI's input popup cannot scroll, so a bridge with dozens of lights or scenes made the lists unusable. The pickers write the list to `hue_scenes_list.txt` in the SAMMI folder and open it in Notepad.
- **TLS.** `curl -k` skips certificate verification for the bridge on your LAN. Windows cannot verify the bridge's certificate anyway, and the app key never leaves your network.
- **Errors are reported, success is silent.** An action button alerts when the bridge rejects a request, when there is no reply, or when a scene slot has nothing linked. A good request produces no message.
- **Discovery needs the internet.** Hue 1 uses Hue's discovery service, which works when the PC and bridge share an internet connection. Hue Config: Set IP is the manual path.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| "'curl.exe' is not recognized" | Very old Windows 10 | Run Windows Update, or install curl from curl.se and add it to the PATH |
| Pair says "link button not pressed" | More than 30 seconds passed | Press the bridge button, then run Pair immediately |
| Empty response from any button | Wrong IP, bridge off, PC and bridge on different networks | Hue: Show Settings, then Hue Config: Set IP |
| "unauthorized user" | App key lost, bridge reset | Press the bridge button, run Hue 2: Pair |
| Action button fires, no error, the lights you watch do not change | The linked scene belongs to another room or zone | Run Hue: Link Scenes and pick a scene under the heading marked as your target |
| "no scene linked for slot 1" | Link Scenes was never run, or the scene was deleted | Run Hue: Link Scenes |
| "Hue rejected the request: ..." | The bridge refused it; the text is Hue's own error | `not found` means re-run Pick Target or Link Scenes; `unauthorized` means re-run Pair |
| Worked for days, then stopped | Router gave the bridge a new IP | Hue 1: Discover, then Hue 4: Test. Auto rediscover does this on SAMMI startup too |

## Building the deck from source

The deck JSON is generated. Do not hand-edit it.

```
python3 tools/build_deck.py
```

This writes `deck/HueScenes.deck.json` (the file to paste into SAMMI), `deck/HueScenes.commands.md` (a readable listing of every button and command, useful for review), and refreshes the JSON block at the top of this README. Python 3.10 or newer, no dependencies.

The generator builds SAMMI's deck format directly: command ids, text boxes and block sizes for If and Repeat. [SAMMI deck JSON format notes](docs/SAMMI%20deck%20JSON%20format%20notes.md) records what was learned about that format and how it was verified. The [Development Plan](docs/SAMMI%20→%20Hue%20Scenes%20—%20Development%20Plan.md) holds the design decisions, risks and test plan.
